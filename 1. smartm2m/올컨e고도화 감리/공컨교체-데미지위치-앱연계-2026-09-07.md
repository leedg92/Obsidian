# 공컨교체 데미지 위치 선택 — 앱 연계 (CHMAN-316)

기존 엔드포인트 그대로. 새 API 없음.

## 1. 사유 조회 — 파라미터 하나 추가

```
GET /mobile/terminalConHandler/terminalContainerHandleRequestData/v2
    ?terminalCode=PNITC050&modalType=SWAP&orderSourceType=...   ← 지금과 동일 (1차 목록)
    &parentCode=0035                                             ← 추가. 데미지 하위 목록
```

- `parentCode` 없음 → 지금과 같은 응답 (청소불량 `0011` · 데미지 `0035` · 악취 `0042`)
- `parentCode=0035` → `containerHandlingReasonList` 에 데미지 위치 8종 (`3501`~`3508`). 형식은 1차와 동일

```json
"containerHandlingReasonList": [
  { "reasonCode": "3501", "reasonMark": "컨테이너 하부" },
  { "reasonCode": "3502", "reasonMark": "위험물 라벨" },
  { "reasonCode": "3503", "reasonMark": "문 (도어)" },
  { "reasonCode": "3504", "reasonMark": "바닥 내부" },
  { "reasonCode": "3505", "reasonMark": "전면 (앞)" },
  { "reasonCode": "3506", "reasonMark": "좌측" },
  { "reasonCode": "3507", "reasonMark": "우측" },
  { "reasonCode": "3508", "reasonMark": "상부" }
]
```

## 2. 교체 요청 — 변경 없음

```
POST /mobile/terminalConHandler/reqeust/terminal/container/swap
```

`reasonCode` 에 최종 선택 코드만 넣는다. 데미지면 하위 코드(예 `3503`), `0035` 는 보내지 않는다.

## 앱 흐름 — 코드값 분기 없이, 고른 코드로 무조건 재조회

1. 사유 다이얼로그 (지금과 동일)
2. 사유 선택 → 1번 API 를 `parentCode=<고른 코드>` 로 재조회
   - 목록 있음 → 하위 선택 다이얼로그 → 하위 코드로 3번
   - 목록 없음 → 고른 코드 그대로 3번
3. 2번 API 로 교체 요청

앱에 `0035` 를 박지 않는다. 하위가 있는지는 응답 목록 유무로만 판단한다.
