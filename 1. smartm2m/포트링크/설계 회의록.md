# 에드온
## 코피노
### 기존 흐름
#### TSS
1. CreateCopino
	- BC -(InvokeAlarm, docKey 포함)-> TA(1) -(MIG create)-> TOS
		- 1 : GetCopino
			- TA <-> BC : TA가 BC로부터 커밋된코피노 정보 받아옴
2. CopinoVerificationResult 
	- TOS -> TA -> BC -(InvokeAlarm)-> Bctrans
#### VBS
1. CreateCopino : 없음
2. CopinoVerificationResult
	- TOS -> TA -> BC -(InvokeAlarm)-> Bctrans / TA(1)
		- 1 : pinNo받아서 터미널내부 TA INF테이블에 저장

### 포트링크 버전(PL이 기존 BC의 역할을 일부 흡수)
#### TSS
1. CreateCopino(가칭) : CORE -> PL(1) -(InvokeAlarm, docKey 생성 및 포함)-> TA(2) -(MIG create)-> TOS
	- 1 : PL이 CORE로 부터 받은 정보를 분해해서 어떤 운송방식인지 판별(조건식 있음)
	- 2 : GetCopino
		- TA <-> PL : TA가 PL로부터 커밋된(척한)코피노 정보 받아옴
		- 인보크알람에서 기존 GetCopino 응답을 보내주는 방향도 고려(TA쪽에서의 GetCopino를 없앤다) - 확정
2. CopinoVerificationResult
	- TOS -> TA -> PL -> BC -> CORE
#### Group
1. CreateCopino(가칭) : CORE -> PL(1) -(InvokeAlarm, docKey 생성 및 포함)-> TA(2) -(MIG create)-> TOS
	- 1 : PL이 CORE로 부터 받은 정보를 분해해서 어떤 운송방식인지 판별(조건식 있음)
	- 2 : GetCopino
		- TA <-> PL : TA가 PL로부터 커밋된(척한)코피노 정보 받아옴
		- 인보크알람에서 기존 GetCopino 응답을 보내주는 방향도 고려(TA쪽에서의 GetCopino를 없앤다) - 확정
2. CopinoVerificationResult
	- TOS -> TA -> PL -> BC -> CORE
#### VBS
1. CreateCopino(가칭) : 없음
2. CopinoVerificationResult
	- TOS -> TA -> PL(1) -> BC -> CORE
		- 1 : TA한테 터미널 내부 TA INF테이블에 저장하기 위한 기존 블록체인 정보와 동일하게 invokeAlarm(pinNo생성 포함, pinNo는 규칙이 있음)
		- 1 : PL이 TA로 부터 받은 정보를 분해해서 어떤 운송방식인지 판별(조건식 있음)
#### 미지정 공컨
1. CreateCopino(가칭) : 없음
2. CopinoVerificationResult
	- TOS -> TA -> PL(1) -> BC -> CORE
		- 1 : TA한테 터미널 내부 TA INF테이블에 저장하기 위한 기존 블록체인 정보와 동일하게 invokeAlarm(pinNo생성 포함, pinNo는 규칙이 있음)
		- 1 : PL이 TA로 부터 받은 정보를 분해해서 어떤 운송방식인지 판별(조건식 있음)
