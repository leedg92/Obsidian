# DGT 터미널 방문 회의록
### 1. VGM 처리 방식

- 무게 정보는 **CLL(BAPLIE)이 우선**임. COPINO가 먼저 들어오면 COPINO 값을 쓰고, CLL이 들어오면 CLL 값으로 덮어씀
- TOS 알고리즘이 무게를 고려해 자동으로 플래닝하고, 플래너가 검토한 뒤 진행함
- **탑헤비 적재**
    - 상단 적재 판단에 VGM 값을 사용함
    - Weight 값과 VGM 값이 다르면 VGM을 우선 적용함
    - PNC(수직 배치)와 DGT(수평 배치)는 플래닝 로직 자체가 다름
- **AGV 운용**: 무게에 따라 AGV 주행속도를 다르게 적용함(무거우면 저속, 가벼우면 고속). 현재 VGM 값을 기준으로 적용 중임
- **CLL 수신 시점**
    - 선적 건은 최소 12시간 전까지 CLL이 들어와야 함
    - 그 이후에도 계속 업데이트할 수 있음
    - 시스템 기반이라 업데이트가 들어오면 바로 반영됨
    - 허용중량 경계 화물(예: 허용 60톤에 59톤)의 처리가 이 시점에 결정됨
- 터미널로 들어오는 무게 단위는 kg으로 통일돼 있음(앞단에서 어떻게 처리되는지는 모름)
- TS도 무게를 체크하지만, 특정 코드를 보내면 체크하지 않음

### 2. 오류·벌금 현황

- 현재 벌금이나 벌점은 부과하지 않음. 앞으로 검토할 수 있다고 함
- 선사 데이터 확인을 요청한 적은 있지만, 크리티컬한 문제는 없었음
- 터무니없는 무게가 전송돼 아예 반입이 안 된 사례가 있음. 이는 단순 입력 에러였음
- 허용 오차 하한선은 모름
- COPINO와 CLL 값이 다르면 화물이 되돌아오는 게 아니라 비용 청구로 처리됨
- 미주 바운드는 무게에 매우 민감함. 선적 거부나 작업 거부가 생기면 큰 문제가 됨
- 수입 화물이 공도에서 과중량 문제를 일으키면(62톤 등) 책임은 운송사·화주에 있음

### 3. 과제에 대한 의견

- VGM은 원래 없던 항목으로, EDI 국제 규격에 따라 추가된 것임. 해외 선사도 많으므로 **국제 규격 검토가 선결 과제**라고 봄
- 플랫폼에서 값이 불일치할 때 **누구에게 책임을 물을지** 정리가 필요함
    - BPA가 책임을 지는 구조가 아니면 실효성이 없다고 봄
- 선사와 운송사가 보내는 무게에 큰 차이가 없어 실효성에 의문이 있음
- PWS의 신뢰성과, 유지보수 비용까지 고려했을 때 지속 가능한지 의문임
- 신규 장비보다 **기존 장비를 활용하는 방향**을 선호함(추가 유지보수 비용 부담)
- **운영상 부가 효용**은 가능성이 있다고 봄
    - 과거 크레인 계측을 시도했지만 흔들림 편차와 정비 비용 문제로 무산됨
    - PWS가 이런 비용을 줄이는 방안이 될 수 있음
- **OCR**
    - 자동화 터미널이라 모든 정보가 중요하며, 계속 튜닝 중임
    - 컨테이너 번호를 COPINO와 대조해 다르면 막는 식의 활용(일부 자리만 체크 등)은 바로 도입할 수 있다고 봄
- KL-Net·KTNET 연계는 DGT에서도 고려하며 논의 중임
